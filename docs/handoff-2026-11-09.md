## 1. 任务脉络（目标是怎么演变的）

1. **读项目**：最初只是读 `edurec-engine` 并解释（V1 = 双塔 DSSM 召回 → 多任务 DeepFM 精排 → MMR 重排）。

   删除 `features/`、`models/`、`pipeline/`、`train_all.py`、`run_batch_infer.py` 与 11 个相关测试
   （提交 `533903e chore: 清空旧模型实现，保留骨架与数据契约`）。
3. **新方案（用户提出）**：第一步给每个资源与学生需求各建嵌入、算距离推荐（参考 CourseHub）；
   第二步把嵌入升级为概率分布（学生需求 = 嵌入空间中以某点为中心的正态分布，参考 U-GLAD / UKT）。
4. **实测后收敛**：阶段一（语义双塔）有效；**阶段二（高斯双塔）无收益，已搁置到独立分支**。
5. **工程闭环**：批量推理 + platform 交接契约（原子写入 + 旁挂信封）+ 文档重写 + 合并推送。
6. **DRG 组会汇报**：MACRO 仓库里 **DRG 实现代码为 0 行**（只有 ChatGLM QLoRA + 四个 prompt 脚本 + 数据）；
   真实视频标题是 71 字营销长标题、训练数据是 9 字学科名（体裁不同）；真正决定性问题是 **ID 空间不重叠**。
   结论：不换模型、改接入方式（标题规范化 + 多期次合并 + 自建共现规则 / 只在候选集构造用 LLM）。
7. **转向 PRISM + EMBEDD-ER**：用户明确 **EMBEDD-ER 不是推荐模型，是生成嵌入的**；**PRISM 是看重其多模态能力**，
   用封面 + 关键帧规避「B 站视频简介/标题与内容无关」；platform 已实现封面与关键帧提取。
   缺的是**推荐主体**，选型结论 = **M3CSR**（但其官方代码不存在，见 §5）。
8. **当前**：把 platform 与 engine 放进同一文件夹，准备新会话继续（本文档即为此准备）。

- MOOCCube 实测（`dataset/MOOCCube/MOOCCube/`）：**706 门课**、199,199 用户、682,753 选课对；
  ≥5 门课 34,917 人、**≥10 门课 6,548 人**；正文均值 404 字、空正文 0。
  加载参数：`max_users=5000`、`min_user_courses=10`、`min_courses_after_sample=8`（抽样是确定性等间隔轮转，可复现）。
- `scripts/gen_sim_data.py` 生成模拟数据；`dataset/platform_snapshot/` 下有 4 个真实快照

### 3.2 文本编码（`src/engine/features/encoder.py`）

- `Encoder` 接口：`fit(corpus)` / `encode(texts)->(n,384) float32`（统一 L2 归一化）/ `encode_one` / `version`。
- 默认 `LocalTfidfSvdEncoder`（名字保留历史）：**字符 n-gram 哈希 + IDF + 固定随机投影**，
  `hash_dim=4096`、`dim=384`、`ngram=(1,2)`、`seed=42`；`fit` 只学 IDF，指纹（sha256 前 12 位）拼进 `version`。
- 对照结论：同类目 Top-10 投票准确率 **0.618**（多数类基线 0.424）；TF-IDF+SVD 只有 0.535、三元组 0.605
  → **SVD 降噪层伤害排序，已删除**。同类目相似度 0.1426 vs 跨类目 0.1287。
- `SentenceTransformerEncoder`（all-MiniLM-L6-v2）只是可插拔占位：本机无外网、未安装该包，暂不可用。
- `CachedEncoder`：文本 sha256 → 向量存 `.npz`（当前缓存 130 MB，`model/encoder_cache_*.npz`）。

### 3.3 阶段一：语义双塔（`src/engine/models/recall/semantic.py` + `trainer.py`）

- 结构：需求塔 / 物品塔各一个 MLP（384→hidden→128），L2 归一化，InfoNCE（`τ=0.05`）。
- 训练样本 `last_prefix`（默认，5,000 条，约 19 s/epoch）；`all_prefixes` 53,147 条（约 256 s/epoch）。
- **防泄漏**：预测第 i 个交互时，需求文本只用前 i-1 条历史构造。
- 评估协议：**1 vs 99 采样候选**（随机 HitRate@10 = 0.0990），三种方法共用同一候选集。

| 方法（MOOCCube，5000 用户 / 706 课） | HR@5 | HR@10 | HR@20 | NDCG@10 | MRR |
|---|---|---|---|---|---|
| 随机 | 0.0495 | 0.0990 | 0.1981 | — | — |
| 纯文本相似度 | 0.2648 | 0.3866 | — | 0.1604 | 0.1972 |
| **纯热门** | **0.3586** | **0.4930** | **0.2174**（NDCG） | | **0.2509** |
| 语义双塔（纯语义） | 0.2864 | 0.4432 | 0.6314 | 0.1710 | 0.1947 |
| **语义 0.6 + 热度 0.4（当前默认）** | **0.4108** | **0.5758** | — | **0.2534** | **0.2791** |

- 关键结论：**纯语义弱于纯热门；融合后比纯热门高约 17.6%**。融合权重扫描最优在 0.5/0.5
  （0.4176/0.5800/0.2576/0.2843），默认取 0.6/0.4 以保留语义权重（`quality_w_semantic=0.6`、
  `quality_w_rating=0.0`、`quality_w_popularity=0.4`）。
- 质量归一化：`normalize_minmax` / `normalize_log` / **`rank_percentile`**（并列取平均秩）。

### 3.4 阶段二：高斯双塔（已实现、已评测、暂不启用）

- 分支 `feat/gaussian-probabilistic`（`7bea821`）：均值 L2 + `softplus` 出的 σ、对角协方差 2-Wasserstein、
  `calibrated_mean = μ·(1−mean(σ²))`（U-GLAD 标量化）。
- **实测无收益**：HR@5 0.2562 / HR@10 0.4108 / NDCG@10 0.1566 / MRR 0.1822，全面低于阶段一。
- 三层诊断：① 方差初版恒为 0.5047，与历史长度无关；② 加 `history_signal` 后方差会动（相关 +0.40），
  但方向相反（历史越长越不确定，真实用户 `history_corr=+0.2855`）；③ 物品侧方差变异系数仅 **0.0026**，
  W₂ 的协方差项近似常数。
- 根因：本任务的学生需求是「拼接文本」，没有序列信息可学不确定性；训练目标也没要求方差解释不确定性。
- 结论文档：`docs/gaussian-recall-status.md`（含重启检查清单与四个可行方向：显式 σ=f(n)、序列建模、
  换评估协议度量保守性、换数据/场景）。

## 5. 推荐主体选型（PRISM / EMBEDD-ER / M3CSR）

### 5.1 两个已有部件

- **EMBEDD-ER**（CSEDU 2023）：Wikifier 维基化 → mention–concept 二部图 + PageRank → Wikipedia2Vec 300d →
  `e = Σ(e_i·p_i)/Σp_i`。任务无关、无需训练；消融显示 Wikipedia2Vec 是核心、PageRank 加权只是锦上添花；
  只验证了分类/相似度，**没做推荐实验**。
- **PRISM**（WWW '26）：4 个交互专家（uni-image / uni-text / synergy / redundancy）+ Adaptive Fusion Layer，
  按 PID 分解做 per-user 模态加权。代码在本机 `PRISM/`（基于 STOSA，`--no_prism/--no_modality/--fusion_only` 三个消融开关），
  离线可跑（自带 `_vendor/ViT-B-32.pt`）；但它是**序列 next-item、ID-based**，冷启弱。

### 5.2 选型结论：M3CSR（Kuaishou，RecSys 2024）

- DOI `10.1145/3640457.3688098`，作者 Gaode Chen 等（通讯 `chengaode19@gmail.com`）。
- 四个机制：① 每模态线性映射到行为空间；② 三模态 concat 后 K-means（约 1000 簇）得 cluster ID 的可学习嵌入；
  ③ 用户塔用 ID 作 Query（stop-gradient）对模态做注意力 + 模态强度 `α_m`；④ 物品塔按训练次数分桶学 gate
  `v_final = Gate·v_id + (1−Gate)·v_multi-modal`（热门靠 ID、新冷靠内容）。
- 线上 A/B：点击 +3.4%、点赞 +3.0%、关注 +3.1%；冷启速度 +1.2%、冷启覆盖率 +3.6%。
- **代码状况：官方未开源，GitHub 无第三方复现**（repo 搜索 0；grep.app/Sourcegraph 无有效命中；
  `gaodechen.github.io` 是同名不同人的 UC Davis 机器人方向；论文无 arXiv 版）。
- 三条路：① 按论文自实现（3~5 天，已有 CLIP 权重 / MOOCCube / 1v99 协议）；② 用有代码的多模态底座
  （MMSSL `HKUDS/MMSSL`、LATTICE、MMGCN、VBPR），但缺 cluster-ID、模态强度、热度门控，冷启增益打折；
  ③ 邮件向作者要代码（工业界论文通常不给）。
- 注意：arXiv `2608.05655` 对 PRISM/M3CSR 这类 per-user 模态加权做受控审计，建议同时保留**固定权重对照组**。

### 5.3 拟拼接方案

```
content = PRISM(cover, keyframes, embedd_er)
item    = Gate(popularity)·id + (1−Gate)·content
user    = Attn(history ids) + Σ_m α_m·Attn_m(content)
score   = <u, i> + quality
```

模态映射：文本 → EMBEDD-ER 概念嵌入（不可用时降级本地 encoder）；视觉 → 封面 CLIP + 关键帧 CLIP；
音频不做；cluster 数 50~100；门控分桶 8~16。
