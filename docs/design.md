## 1. 概述与交付边界

edurec-engine 是教育资源推荐引擎，作为 edurec-platform 的独立服务被调用，用于首页推荐流。

**一期边界：离线训练 + 批量推理。** 推荐结果写回平台 `recommendations` 缓存表；
在线 REST 服务（二期）不做。两仓库之间**只有文件交接**，不共享数据库与代码。

### 1.1 核心思路的演进

V1 走的是工业界经典两段式（协同过滤式的双塔召回 + 多任务精排）。
V2 换了一个起点：**用文本嵌入把「资源内容」与「学生需求」映射到同一语义空间，
用距离衡量匹配度**，参考 CourseHub（语义课程推荐框架）。

这么换的理由：

- V1 的召回依赖 `user_id`/`item_id` 的嵌入，**冷启动用户与新资源没有可用表示**；
  V2 的表示来自内容文本，新资源一上线就有向量；
- 平台的 `users` 表**没有任何人口属性**（§3.1），V1 的画像只能从行为反推，
  行为稀疏时画像近乎均匀分布；V2 允许直接用需求文本（学习目标/查询）表达意图；
- CourseHub 的实证结论是：语义相似度 + 质量信号的复合打分显著优于
  BM25 / TF-IDF / DPR / ColBERT。

### 1.2 与 CourseHub 的差异（以及为什么）

| 维度 | CourseHub | 本引擎 | 原因 |
|---|---|---|---|
| 学生侧输入 | 查询文本（用户实时输入） | **行为历史反推的需求文本** | 平台没有查询/学习目标字段（§3.1） |
| 是否训练 | 不训练，编码即表示 | **训练双塔投影** | 纯文本相似度实测弱于训练后的投影（§5.3） |
| 质量信号 | 评分 + 热度，权重 (0.7, 0.2, 0.1) | 热度为主，权重按本数据实测调整 | 本数据集无评分；实测最优权重与论文不同（§7） |
| 检索 | 全量余弦 | 全量点积（不建 ANN） | 资源量小（706 门课），全量更简单精确 |

## 3. 数据层

### 3.1 平台数据上下文（必须兼容的 schema）

平台 MySQL 中与 engine 相关的表：

- `users(id, username, display_name, …)` —— **无人口属性字段**，画像只能从行为反推
- `resources(id, title, description, type[course|article|video], category_id,
  tags JSON, metadata JSON, avg_rating, view_count, created_at)`
- `categories(id, name)`
- `user_behaviors(id, user_id, resource_id, action[view|click|favorite], created_at)`
- `ratings(id, user_id, resource_id, score 1-5, …)`
- `recommendations(id, user_id, resource_ids JSON, created_at)` —— 结果缓存表

**关键约束（直接决定模型形态）**：

1. `resources.description` 是语义召回**唯一的文本信号来源**。
   平台表里有该字段，但当前 `export_snapshot` 未导出——这是当前最大的阻塞项（§11.1）。
2. `users` 无任何文本/属性 → 学生需求只能从**行为历史**反推。
3. `user_behaviors` 有 `created_at` → 可以做**时间序切分**，防时序泄漏。

### 3.2 统一 schema

所有数据源在入口归一为同一套 `DataBundle`：

```python
@dataclass(frozen=True)
class Resource:
    resource_id: int
    type: str
    category_id: int
    tags: tuple[str, ...] = ()
    metadata: dict = field(default_factory=dict)
    description: str = ""        # 正文，语义嵌入的文本来源；缺失时降级为空串

@dataclass(frozen=True)
class Behavior:
    user_id: int; resource_id: int; action: str; ts: int
```

`description` 是 V2 新增的一等字段（V1 把正文塞在 `metadata` 里）。

### 3.3 三个数据源

| 数据源 | 用途 | 规模（本机实测） | 文本质量 |
|---|---|---|---|
| `sim` 模拟器 | 打通流水线、回归测试 | 2000 用户 / 500 资源 / 10 万行为 | 按类目主题合成，可编码 |
| `mooccube` | **真实数据验证** | 706 门课 / 5000 活跃用户 / 7.5 万选课 | 课程简介，正文均值 404 字 |
| `platform` | 平台真实快照 | 取决于快照 | **待 platform 补导 `description`（§11.1）** |

**MOOCCube 映射规则**（`data/mooccube.py`）：

- 推荐单元 = **课程**，对齐平台 `resources` 抽象与 CourseHub 的做法；
- `about`（富文本）去标签后作为 `description`；
- `category_id` 取自该课程概念的**学科领域**（概念 ID 后缀，如 `K_活性炭_化学` → `化学`），
  使文本与类目天然对齐；
- 字符串 ID（`C_…` / `U_…`）排序后确定性编号，原始 ID 保留在
  `metadata["source_id"]` 与 `id_map`，供交接反查；
- 数据集只有**选课行为、没有评分**，因此 `ratings` 诚实留空。

**为什么不继续用 MovieLens**：V1 用 MovieLens-1M 做有效性验证。
V2 需要的是**内容文本**，而 MovieLens 只有电影名与类型标签，没有长文本描述；
MOOCCube 的课程简介正是教育域的真实文本，领域也更契合。

### 3.4 学生需求文本的构造

平台没有查询字段，因此需求由**行为历史反推**：

```
需求文本 = 该用户最近交互过的 N 门课的「标题 + 正文」按时间拼接
           （N = recall_max_need_items，默认 20）
```

**为什么按时间取最近的**：越近的行为越能代表当前需求。
**为什么只取资源文本**：不含用户侧信息，因此不同用户对同一资源得到同一文本，
资源编码可以全局缓存复用。

## 4. 文本编码层

### 4.1 为什么需要「可插拔」

设计目标是用 transformer 句向量（论文用 `all-MiniLM-L6-v2`，384 维）。
但开发环境**无外网**：`sentence-transformers` 装不上、模型权重下不来
（`huggingface.co` / `hf-mirror.com` 均 SSL 失败）。
因此把编码器抽象成接口，本地降级实现先跑通全链路，环境就绪后一行配置切换。

```python
class Encoder(ABC):
    def fit(self, corpus): ...                  # 统计型编码器需要先拟合语料
    def encode(self, texts) -> np.ndarray: ...  # (n, dim) float32，L2 归一化
```

| 实现 | 说明 |
|---|---|
| `LocalTfidfSvdEncoder` | 本地降级：字符 n-gram 哈希 + IDF 权重 + 固定随机投影 |
| `SentenceTransformerEncoder` | 真 transformer 占位，默认 `all-MiniLM-L6-v2`；调用时才 import 并给出可操作报错 |
| `CachedEncoder` | 装饰器：`文本 hash → 向量` 落盘 `.npz`，原子替换 |

### 4.2 本地降级实现的三个关键取舍

**（1）输出维度必须恒定。** 常规写法「TF-IDF + TruncatedSVD」的 `n_components`
受样本数约束（必须小于 `n_samples`），小语料上 384 维会被夹到几维。

**（2）编码器必须是「文本的纯函数」。** 否则 `CachedEncoder` 的
「同一文本 → 同一向量」假设失效，缓存不可靠。

因此拆成两部分：

- **与语料无关**：字符 n-gram → 哈希到固定维度 → 固定随机投影到 `dim`。投影基只由
  `dim` 与 `seed` 决定，**输出维度恒等于 `dim`**；
- **依赖语料**：只在语料上学一份 IDF 权重，并把**语料指纹**拼进 `version`，
  使缓存随语料自动失效。

**（3）SVD 降噪层实测有害，已移除。** 对照实验（MOOCCube 706 门课，
Top-10 最近邻类目投票准确率）：

| 方案 | 同类目-跨类目 gap | Top-10 类目准确率 |
|---|---|---|
| TF-IDF + SVD 权重 | +0.0114 | 0.535 |
| log1p + IDF | +0.0125 | 0.483 |
| **二元组 + 原始计数 × IDF（采用）** | **+0.0139** | **0.618** |

多数类基线为 0.424，即采用方案显著优于基线。

### 4.3 已知局限（必须如实说明）

本地降级实现只能抓**字面/词形层面**的关联，抓不住「特征值 vs 线性变换」这类
**纯语义远距离关联**——这正是要等真 transformer 的部分。
一个直观例子：查询「线性代数。矩阵、向量空间与特征值」时，它确实召回了三门线性代数课
（相似度 0.467 / 0.446 / 0.438），但靠的是字面重合。

## 5. 召回模型：语义双塔（阶段一）

### 5.1 结构

```
资源文本 ──Encoder──► e_i ──ItemTower(MLP 384→256→128)──► item 向量 ─┐
                                                                     ├─ 内积打分
学生行为历史 ──拼文本──►Encoder──► e_u ──StudentTower──► user 向量 ───┘
```

两个塔都作用在**同一编码器输出空间**上，因此：

- 资源向量可**离线预计算**，推理时只剩学生塔一次前向；
- 一期是**全量点积**，不建 ANN 索引（706 门课，全量更简单精确）；
  资源量大后把资源矩阵交给 faiss 即可，接口不变。

输出 L2 归一化，因此内积即余弦相似度——与 CourseHub 的度量一致。

### 5.2 训练目标与数据构造

**损失**：InfoNCE / in-batch softmax。

```
L = -log( exp(<u_i, i⁺>/τ) / Σ_j exp(<u_i, i_j>/τ) )     τ = 0.05
```

负样本来自 batch 内其它资源的向量（零构造开销），可选再拼入若干热门资源
（抑制「全推热门」的偏置）。

**数据构造（防泄漏是重点）**：

```
对每个用户，按时间排序他的交互：
    预测第 i 个交互时，需求文本只能用前 i-1 个交互构造
    ——否则「需求」里含有了待预测的那门课，等于把答案抄进输入
```

两种样本模式：

| 模式 | 含义 | 样本量（MOOCCube 5000 用户） | 单 epoch 耗时 |
|---|---|---|---|
| `all_prefixes` | 每个交互都作正样本 | 53,147 | ~256 s |
| `last_prefix`（默认） | 每用户只用最后一个交互 | 5,000 | ~19 s |

`last_prefix` 快约 10 倍，且更贴近线上形态（用全部已知历史推下一步），因此设为默认。

### 5.3 为什么是「训练的双塔」而不是「编码即表示」

CourseHub 不做训练，直接用查询编码与课程编码的余弦相似度。
本引擎保留训练，是因为实测表明训练有增量（同一协议下）：

| 方法 | HitRate@5 | HitRate@10 | NDCG@10 | MRR |
|---|---|---|---|---|
| 纯文本相似度（不训练） | 0.2648 | 0.3866 | 0.1604 | 0.1972 |
| **训练后双塔** | **0.2864** | **0.4432** | **0.1710** | 0.1947 |

即：可学习的投影确实带来了额外收益（HitRate@10 +14.6%），因此保留训练环节。

### 5.4 冷启动

无行为的用户（平台全新用户）**没有需求文本**，直接走热门兜底。
这比给一个空的/均匀的需求向量更诚实——引擎无法对未知需求做个性化。

## 6. 概率式表示（阶段二，暂不启用）

### 6.1 设想

阶段一把需求与资源表示成空间里的**一个点**，表达不了两件事：
需求本身的不确定性（历史只有 1~2 门课）与兴趣的多峰性。

阶段二把表示升级为分布 `N(μ, Σ)`，用 **2-Wasserstein 距离**衡量差异，参考：

- **UKT**：均值 + 协方差嵌入表示学生状态，用 2-Wasserstein 做相似度；
- **U-GLAD**：用方差校准期望 `ĥ = μ ⊙ (1 − σ²)`，不确定性高时表示更保守。

实现采用**对角协方差**（`Σ = diag(σ²)`），此时 2-Wasserstein 有闭式解：

```
W₂² = ‖μ_u − μ_i‖² + Σ_d (σ_u,d − σ_i,d)²
```

### 6.2 实测结论：不产生收益

| 方法 | HitRate@5 | HitRate@10 | NDCG@10 | MRR |
|---|---|---|---|---|
| 阶段一（点表示） | **0.2864** | **0.4432** | **0.1710** | **0.1947** |
| 阶段二（分布表示） | 0.2562 | 0.4108 | 0.1566 | 0.1822 |

**根因**：方差没有区分度。资源侧方差变异系数仅 **0.26%**（均值 0.5019、标准差 0.0013），
因此 W₂ 的协方差项在排序中近似常数；补入历史长度信号后方差虽有响应（相关 +0.40），
但**符号与假设相反**（历史越长方差越大）。

**为什么论文方法在此失效**：UKT/U-GLAD 有交互**序列**（时序建模能暴露行为的矛盾与稀疏），
而本任务的学生需求只是**拼接文本**，不含「历史有多短/多矛盾」的信息。

**完整分析、复现命令与四个后续方向见 `docs/gaussian-recall-status.md`**；
代码保留在 `feat/gaussian-probabilistic` 分支。

## 7. 质量信号融合

CourseHub 的复合打分函数：

```
score_i = w₁ · sim(q, c_i) + w₂ · ratinĝ_i + w₃ · popularitŷ_i
```

**归一化方式按信号分布选择**（这是实测踩出来的）：

| 信号 | 方法 | 原因 |
|---|---|---|
| 评分 | min-max | 分布有天然上下界（1~5 分） |
| 热度 | **秩百分位** | 零值占多数（706 门课里 50 门零交互）。min-max 会把零交互算成「中等热度」，盖过语义信号；秩百分位把零压在长尾低分位，且**信号全零时返回全 0**，不给每门课白加常数 |

**权重按本数据集实测调整**（MOOCCube 无评分，rating 权重为 0）：

| 语义权重 | 热度权重 | HitRate@5 | HitRate@10 | NDCG@10 | MRR |
|---|---|---|---|---|---|
| 1.0 | 0.0 | 0.2864 | 0.4432 | 0.1710 | 0.1947 |
| 0.7 | 0.3 | 0.3846 | 0.5434 | 0.2360 | 0.2658 |
| **0.6 / 0.4（默认）** | | 0.4108 | 0.5758 | 0.2534 | 0.2791 |
| 0.5 | 0.5 | 0.4176 | 0.5800 | 0.2576 | 0.2843 |
| 0.0 | 1.0（纯热门） | 0.3586 | 0.4930 | 0.2174 | 0.2509 |

**这是本项目最重要的实证发现**：

1. **纯语义单独不够强**（0.4432），甚至弱于纯热门（0.4930）；
2. **融合后显著超过纯热门**（0.5800，+17.6%）——说明语义信号有增量，只是不能单独用；
3. 论文的 (0.7, 0.2, 0.1) 是在自建 MOOC 数据上网格搜索得到的，
   **不能照抄**到本数据集（本数据集热度信号占比要更高）。

## 8. 评估方案

### 8.1 为什么不能用「全量候选 + 留出未来课程」

最初设计是：对每个用户，用训练期历史推测试期课程，在全量资源上排名。
在 MOOCCube 上这套协议**失效**：

- 测试期交互中 **98.9%** 对应的课程在训练期已被**别的用户**选过，
  资源塔对它们有嵌入记忆；
- 全量候选 697 门而正样本仅约 2 个，指标极低且难以区分模型。

### 8.2 采用的协议：1 vs N 采样候选

对每个用户构造候选集 = **他测试期选过的课** + **N 门他没选过的课**
（默认 N=99，共约 101 个候选）。

- 随机排序的期望 HitRate@K ≈ K / |候选| → **随机基线明确**（@10 = 0.0990）；
- 三种评估（双塔 / 纯文本 / 热门）**共用同一批候选集**，否则横向比较不成立。

### 8.3 防泄漏（两条都不能少）

1. **需求只用训练期历史构造**——若需求含测试期课程，等于把答案抄进输入；
2. **候选里屏蔽训练期已交互的课程**——否则「已选过的课」因 ID 记忆天然得高分，
   指标虚高。

### 8.4 指标

| 指标 | 回答的问题 | 用在 |
|---|---|---|
| Recall@K | 相关项里有多少落在前 K | 召回 |
| HitRate@K | 前 K 是否命中（0/1） | 召回/端到端 |
| NDCG@K | 位置加权的命中质量 | 召回/端到端 |
| MRR | 首个命中位置的倒数 | 召回 |
| AUC | 二分类区分度（**并列分数取平均秩**） | 排序 |

> AUC 实现细节：`argsort` 不是稳定排序，若直接按名次累加，
> 完全并列时会把正样本排到末尾而得出 AUC=1.0（严重高估）。必须用平均秩。

### 8.5 对照基线（必须有，否则无法判断模型是否有效）

1. **纯文本相似度**（不训练）：判断「训练到底有没有用」；
2. **热门排序**：判断「个性化到底有没有用」；
3. **随机**：给出指标的量纲参照。

没有这三条线，任何指标数字都无法解读。

## 9. 批量推理与交接

```
加载模型（校验编码器版本 + 资源语料指纹）
  → 遍历全量用户：
       有历史 → 需求文本 → 语义分 → 质量融合 → 降序
       无历史 → 热门兜底
  → 过滤该用户已交互的课程 + 去重 → top-N
  → 写出 recommendations.json（+ 旁挂信封）
```

**交接契约**（`docs/platform-contract.md`）的硬约束：

| 约束 | 实现 |
|---|---|
| 主文件顶层只有 `{user_id: [resource_id]}` | 元信息一律放旁挂信封，主文件不加任何兄弟字段 |
| 键为十进制整数、值为整数数组 | 出口自检，实测 5000 用户全通过 |
| 无 BOM 的 UTF-8 | `encoding="utf-8"` |
| **先写临时文件再原子重命名** | `*.tmp` + `os.replace`，避免 platform 读到写了一半的文件 |
| 覆盖全量用户 | 遍历 `bundle.users`，冷启动计数并上报 |
| 自行去重、按相关性降序 | 出口处理 |

**口径一致性校验**：推理前比对 `encoder_version`（参数）**与资源语料指纹**（数据），
不一致时**明确报错退出**而非静默产出错误推荐。
只校验版本是不够的——它反映参数，不反映语料。

## 10. 技术选型与决策记录

| # | 决策项 | 选择 | 依据 |
|---|---|---|---|
| 1 | 技术栈 | Python + PyTorch + scikit-learn | ML 生态成熟；TF-IDF/哈希用 sklearn |
| 2 | 整体范式 | 语义嵌入召回（非协同过滤） | 冷启动友好；平台无用户属性，需求可从行为反推 |
| 3 | 推荐单元 | 课程（MOOCCube）/ 资源（平台） | 对齐平台 `resources` 抽象与 CourseHub |
| 4 | 编码器 | 接口 + 本地降级 + 真 transformer 占位 | 开发环境无外网，但架构不因此将就 |
| 5 | 召回结构 | 可训练双塔（非编码即表示） | 实测训练优于纯文本相似度（§5.3） |
| 6 | 检索 | 全量点积，不建 ANN | 资源量小；接口预留 faiss |
| 7 | 负采样 | in-batch + 可选热门负样本 | 零构造开销；缓解「全推热门」 |
| 8 | 概率式表示 | **已实现但不启用** | 实测无收益，根因是方差无区分度（§6） |
| 9 | 质量融合权重 | **0.6 / 0.0 / 0.4**（非论文的 0.7/0.2/0.1） | 本数据集实测最优；无评分故 rating 权重为 0 |
| 10 | 评估协议 | 1 vs N 采样候选 | 全量候选在 MOOCCube 上失效（§8.1） |
| 11 | 训练/推理口径 | 校验语料指纹，不一致即报错 | 防止静默产出错误推荐 |
| 12 | 交付边界 | 离线训练 + 批量推理 | 契合平台推荐缓存表 |

## 11. 已知限制与后续方向

### 11.1 阻塞项（需要 platform 配合）

**`resources.csv` 未导出 `description`。** 语义召回的全部信号来自资源正文，
而当前快照只有 `title`。平台 `resources` 表本就有 `description TEXT` 字段，
只是 `export_snapshot` 没导出。engine 侧已做向后兼容（缺失降级为空串、不报错），
**补导不构成破坏性变更**。变更请求见 `docs/platform-description-request.md`。

在此之前，`platform` 数据源上的语义模型基本失效（不报错，但推荐质量接近热门兜底）。

### 11.2 模型层面的限制

1. **本地编码器语义能力有限**（§4.3）。真 transformer 就位后需重跑指标，
   §7 的权重 0.6/0.4 也可能需要重新网格搜索（语义信号变强后最优权重会移动）。
2. **纯语义弱于热门**（§7）。这说明在当前数据上「用户会选什么」主要由流行度驱动，
   个性化信号偏弱。MOOCCube 选课行为稀疏（每人中位 6 门）是原因之一。
3. **概率式表示未生效**（§6）。

### 11.3 工程层面的待办

1. `platform.py` 尚未校验 `meta.json` 的 `files_sha256`（契约建议项，能挡住拷贝中断）；
2. 尚未做多路召回合并；一旦合并，出口必须补显式去重
   （单路候选天然唯一，多路会重复）；
3. `metadata["created_at"]` 未用于「新资源加权」，快照提供了该字段。

### 11.4 可能的后续方向

| 方向 | 预期收益 | 成本 |
|---|---|---|
| 接入真 transformer 编码器并重调权重 | 中高（语义信号变强） | 低（换配置 + 重跑） |
| 补导 `description` 后在 platform 真实数据上验证 | 高（唯一有效的落地验证） | 低（依赖 platform 配合） |
| 让学生需求更接近真实意图（查询/学习目标） | 高 | 中（需 platform 新增字段） |
| 序列建模学生行为（支持不确定性） | 未知 | 高（见警告文档方向 2） |
| 多路召回（语义 + 协同 + 图） | 中 | 中（须处理去重与分数融合） |
