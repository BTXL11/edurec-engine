# 融合探针：从「自适应图文」到三次负结果

本文记录 `scripts/run_fusion_probe.py` 这轮实验的完整经过。结论先说：**融合机制本身可用，但冻结的 CLIP 内容表示在 Beauty 上信号太弱，三次协议下都没能战胜强序列主干**。过程中还修掉三个会让结果虚高的方法学问题，一并记在下面。

## 1. 问题

目标是把 STOSA（序列主干）与 PRISM 式的多模态信号接起来，并检验一个假设：

> 学生越迷茫，越该看内容本身；目标越明确，越该信历史行为。

实现上就是「内容权重随用户不确定性上升」的自适应门控，我们叫它**自适应图文**。

## 2. 方法

### 2.1 两路信号

- **ID 路**：用户侧用 `DistSAModel.finetune` 取最后一个位置的高斯（均值 + 对角方差）；物品侧用 `item_mean_embeddings` 与 `elu(item_cov_embeddings) + 1`；打分用 Wasserstein-2（`‖μu−μi‖² + ‖σu−σi‖²`）。
- **内容路**：CLIP 图文特征（text/image 各 512 维拼接）。嵌层融合时用岭回归映射到 64 维行为空间；分数级融合时改为「历史 CLIP 均值向量」与候选的余弦。

### 2.2 门控

```
g = floor + (1 − floor) · sigmoid(a · z(disp) + b)
```

`disp` 是历史物品均值的平均平方距离（兴趣离散度），`z` 用验证集统计量标准化。`floor` 是内容权重下限——它是第一轮实验失败后加上的：没有下限时门控可以把内容权重压到 0，等于放弃内容路。

### 2.3 评估协议

- 用户序列取最后一条为目标、前面为历史，负样本 99 个，1 vs 99 采样；各配置共用同一候选集，因此可逐用户配对检验（McNemar + 自助法 95% CI）。
- 验证集用倒数第二条为目标（`u[:-2] → u[-2]`），测试集用最后一条（`u[:-1] → u[-1]`）。

## 3. 三轮实验

### 3.1 第一轮：平均表示 + 嵌层融合（历史数字，不可采信）

早期用户表示是「最近 5 条物品的精度加权平均」，CLIP 用岭回归映射进行为空间。当时全量 22,363 用户上的数字是：

| 配置 | HR@10 | NDCG@10 | MRR |
|---|---|---|---|
| 纯 ID | 0.2581 | 0.1565 | 0.1446 |
| 纯图文 | 0.2441 | 0.1314 | 0.1199 |
| 固定 0.5 | 0.2776 | 0.1672 | 0.1535 |
| 自适应图文 | 0.3331 | 0.1888 | 0.1660 |

看起来很好（+7.5%）。**但这一轮带着第 4 节的两个缺陷，数字只保留作对照**。

### 3.2 第二轮：接真编码器后，嵌层融合塌了

修掉缺陷后再接 STOSA 编码器（2,000 用户冒烟）：

| 主干 | 纯 ID | 纯图文 | 固定 0.5 | 自适应 |
|---|---|---|---|---|
| 平均表示 | 0.1545 | 0.2570 | 0.3060 | 0.3115 |
| STOSA 编码器 | 0.32–0.45 | **0.05–0.075** | 0.09–0.14 | 低于纯 ID |

诊断：编码器用户均值与真实下一物品的余弦 = 0.085（随机 0.004），但与「岭回归映射后的图文向量」只有 0.0265——两路不在一个坐标系里。

### 3.3 第三轮：分数级融合

不再映射到行为空间，两路各自出名次再按门控加权（名次分 `1 − pos/(N−1)`，CLIP 特征先做全库均值中心化）。

全量 22,363 用户（重跑后的最终数字）：

| 配置 | HR@10 | NDCG@10 | MRR |
|---|---|---|---|
| 纯 ID | **0.4355** | **0.2968** | **0.2717** |
| 纯内容 | 0.1162 | 0.0572 | 0.0623 |
| 固定 0.5 | 0.2578 | 0.1413 | 0.1304 |
| 门控 trace | 0.3657 | 0.1980 | 0.1697 |
| 门控 disp | 0.3652 | 0.2040 | 0.1764 |
| 自适应图文 | 0.3647 | 0.2043 | 0.1768 |

配对检验：自适应 vs 固定 **+0.1069**（CI[+0.1025,+0.1116]，p≈0）；自适应 vs 纯 ID **−0.0708**（CI[−0.0754,−0.0662]，p=1.7e−143）；固定 vs 纯 ID −0.1777；纯内容 vs 纯 ID −0.3194；trace 门控 vs 固定 +0.1079。

验证集选出的门控是 `floor=0.00, slope=+0.50`：机制学出了「只在迷茫时补一点内容」，但内容一路太弱，补进去仍在拖累。

### 3.4 冷启动协议

5-core 数据没有真正的冷物品（训练段完全没出现的只有 9 个，命中 52 个用户）。改用「训练段出现次数 ≤ 5」当冷端：物品池 3,514 个（29.0%），末位物品落池的用户 4,446 个（19.9%），候选只从池内采样。

| 配置 | HR@10 | NDCG@10 | MRR |
|---|---|---|---|
| 纯 ID | **0.2537** | **0.1562** | **0.1470** |
| 纯内容 | 0.1138 | 0.0602 | 0.0665 |
| 固定 0.5 | 0.1757 | 0.0921 | 0.0905 |
| 门控 trace | 0.1928 | 0.0997 | 0.0953 |
| 门控 disp | 0.1948 | 0.1008 | 0.0956 |
| 自适应图文 | 0.1991 | 0.1193 | 0.1160 |

自适应 vs 纯 ID **−0.0547**（p=4.8e−16）；自适应 vs 固定 +0.0234（p=1.7e−4）；固定 vs 纯 ID −0.0780；纯内容 vs 纯 ID −0.1399。

**门控这次学对了**：按离散度四分桶，内容权重 0.098 → 0.937 → 1.000 → 1.000，完全符合「越迷茫越看内容」。

| 桶 | disp | g | 纯 ID | 纯内容 | 自适应 |
|---|---|---|---|---|---|
| Q1 | 2.03 | 0.098 | 0.4505 | 0.1097 | 0.4335 |
| Q2 | 2.73 | 0.937 | 0.2295 | 0.1089 | 0.1260 |
| Q3 | 3.08 | 1.000 | 0.1737 | 0.1152 | 0.1152 |
| Q4 | 3.56 | 1.000 | 0.1610 | 0.1214 | 0.1214 |

方向对，接不住：迷茫桶里自适应 ≈ 纯内容，等于把 ID 全扔掉。

有对照意义的是温热侧（全量协议）的四个桶：内容权重只落在 0.157–0.473，自适应在每个桶都输给纯 ID（Δ −0.040 到 −0.084）——门控不敢全信内容，也确实不该全信。

## 4. 修掉的三个方法学问题

### 4.1 验证/测试切分泄漏

早期 `valid_users` 传的是完整序列，而评估函数用 `u[-1]` 当目标——验证与测试是同一个切分，只差负样本 seed。门控选参因此偏乐观。已改为 `valid_users = [u[:-1] ...]`，目标变成 `u[-2]`。

### 4.2 岭回归在评估物品上「背答案」

CLIP→行为空间的映射原来在全量物品上拟合，5 折交叉拟合后**留出物品 R² = −0.062**（样本内 0.53）：映射对没见过的物品还不如直接猜均值。嵌层融合里图文侧的高分有相当部分来自记忆。已改为默认 5 折交叉拟合（`--ridge-folds 5`）。

### 4.3 负采样可能重复

旧实现是拒绝采样，同一个物品可能被抽两次（稀有但会在 99 个候选里重复计分）。改为在「可用物品集合」上不放回抽样；池子小于所需负样本数时才允许放回。指标因此有千分之几的位移，本文件数字均为修复后重跑结果。

## 5. 内容路到底有多弱

三种用户画像在 3,000 用户上的纯内容 HR@10：

| 画像 | HR@10 | MRR |
|---|---|---|
| 最近 5 条均值（现用） | 0.1550 | 0.0878 |
| 最近一条 | 0.1337 | 0.0757 |
| 历史最大相似度 | 0.1553 | 0.0931 |

随机基线是 0.10。换池化方式没用——**信号弱在冻结的 CLIP 向量本身**，这也解释了 PRISM 为什么必须端到端训练多模态分支：它的增益来自学出来的变换，不是余弦相似度。

## 6. 与 PRISM 的差别

PRISM 的四个专家按信息类型分工（图像独有 / 文本独有 / 协同 / 冗余），用 triplet 与余弦辅助损失训练；门控 `MLPReWeighting(5→4)` 的输入含 `id_emb = item_embeddings.mean(dim=1)`，但 ID 只当门控输入、不进入融合。

我们这版是两个分支、门控输入只有兴趣离散度、没有任何辅助损失，内容表示是冻结的。差别就在这里：**PRISM 学专家，我们学一个一维门控**。

## 7. 局限

1. 内容侧是冻结的 CLIP 均值/余弦，没有训练。
2. 5-core Beauty 造不出规模的冷启动（训练段未见物品只有 9 个）。
3. 单数据集、单 checkpoint、1 vs 99 采样，未做全排序。
4. 门控是逐用户标量，没有交互特征。

## 8. 结论

- 融合机制有效：两次实验里自适应都显著优于固定权重（+0.107 / +0.023）。
- 嵌层融合在强序列主干上不成立：两路坐标系不一致，映射后图文侧塌陷。
- 分数级融合绕开了坐标系，但**内容信号本身只有约 0.115 HR@10（随机 0.10）**，掺进去必然拖累。
- 「越迷茫越看内容」在门控层面被数据支持（冷启动协议里权重单调升到 1.0），但需要与它匹配的内容表示才能变成增益。

## 9. 复现

```bash
# 嵌层融合（旧对照，默认 avg 主干）
python -m scripts.run_fusion_probe --fusion embedding --backbone avg \
  --out model/fusion_probe.json

# 真编码器 + 嵌层融合
python -m scripts.run_fusion_probe --fusion embedding --backbone stosa \
  --out model/fusion_probe_stosa.json

# 分数级融合（默认）
python -m scripts.run_fusion_probe --fusion score --backbone stosa \
  --out model/fusion_probe_score.json

# 冷启动协议
python -m scripts.run_fusion_probe --fusion score --backbone stosa \
  --cold-threshold 5 --out model/fusion_cold5.json
```

依赖：`STOSA/outputs/` 下复现 checkpoint、`PRISM/data_local/Beauty/` 下的 CLIP 特征（二者都不入库）。`model/` 是 gitignore 目录。
