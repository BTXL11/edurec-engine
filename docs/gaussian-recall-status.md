# 概率式（高斯）召回：现状警告与可行方向

> **状态：已实现、已评测、暂不启用。**
> 代码在分支 **`feat/gaussian-probabilistic`**（提交 `7bea821`），**不在主线**。
> 本文档在主线保留，是为了让后来者先看到结论，而不是重新踩一遍坑。
>
> 一句话结论：**在当前数据（MOOCCube）上，把表示从「一个点」升级为「一个分布」
> 不会带来任何收益，且稳定地更差。** 根因不是实现 bug，而是方差学不到任何有效信息。

---

## 1. 原始设想

- **阶段一**：给每个资源与学生需求各建一个嵌入，用余弦/内积衡量距离（CourseHub 式）。
- **阶段二**：把嵌入升级为**概率分布**——学生需求是嵌入空间中以某点为中心的正态分布，
  资源同理，用分布之间的距离衡量匹配度。
  参考 **UKT**（均值 + 协方差嵌入，2-Wasserstein 距离）与
  **U-GLAD**（用方差校准期望 `ĥ = μ ⊙ (1 − σ²)`，不确定性高时表示更保守）。

设想中概率式的价值在于：表达「一个学生同时喜欢两三个方向」（多峰）与
「历史很少、需求模糊」（不确定），从而在**历史稀疏/冷启动**用户上更好。

## 2. 实测结果（MOOCCube，5000 活跃用户 / 706 门课 / 1 vs 99 采样候选）

| 方法 | HitRate@5 | HitRate@10 | HitRate@20 | NDCG@10 | MRR |
|---|---|---|---|---|---|
| 阶段一（确定性点表示） | **0.2864** | **0.4432** | **0.6314** | **0.1710** | **0.1947** |
| 阶段二（高斯分布表示） | 0.2562 | 0.4108 | 0.6082 | 0.1566 | 0.1822 |
| 热门排序（对照） | 0.3586 | 0.4930 | 0.6682 | 0.2174 | 0.2509 |
| 随机（对照） | 0.0495 | 0.0990 | 0.1981 | – | – |

**历史稀疏协议下同样没有优势**（把训练期历史截到最近 2 条模拟模糊需求）：
阶段一 HitRate@10 = 0.3396，阶段二 = 0.3346。

## 3. 根因：方差没有区分度（这是关键，不是「再调调参」能解决的）

分三步诊断，结论是**机制本身不成立**：

**（1）方差是常数，与输入无关。**
资源侧方差的均值 0.5019、标准差 0.0013，**变异系数仅 0.26%**；
需求侧均值 0.5075。也就是说 W₂ 的协方差项 `Σ_d (σ_a,d − σ_b,d)²` 在排序中**近似常数**，
对排序没有任何贡献——模型退化成了「只用均值的内积」，还要额外付出参数与训练成本。

**（2）补了「历史长度」作为输入后，方向还是反的。**
直觉上该由「历史长度」告诉模型需求有多模糊，于是把 `log1p(n)/log(21)` 拼进需求塔。
方差**确实开始响应**了（相关系数 +0.40），但**符号与假设相反**：历史越长、方差越大。
诊断命令与结论见 `GaussianTwoTower.uncertainty_report()`。

**（3）方差校准一致地降低指标。**
U-GLAD 式校准 `ĥ = μ ⊙ (1 − mean(σ²))` 在两种协议下都让指标下降
（完整协议 HitRate@10 0.4256 → 0.4162）。这**符合理论**：
当方差没有信息量时，校准就是纯粹的破坏。

**为什么 UKT / U-GLAD 能行而这里不行：**
它们有交互**序列**（时序建模能暴露行为的矛盾、波动与稀疏，方差因此有可学的信息来源），
而本任务的学生需求只是**把历史资源的文本拼接起来的一段文本**——
文本里不含「历史有多短、有多矛盾」的信息。
方差正则项只能保证方差**不塌缩**，训练目标里没有任何一项要求它去解释不确定性，
所以它学不出来。

**已排除的误会**（避免后人重复）：
- 不是正则项缺失 → 加了方差正则，仍无区分度；
- 不是正则项符号写错 → 曾把符号写反（`+log σ²` 反而鼓励塌缩），修正后结论不变；
- 不是缺少不确定性输入 → 补了历史长度信号，方向仍与假设相反；
- 不是训练不充分 → loss 正常下降（5.55 → 3.64），双塔结构与阶段一相同。

## 4. 当前处置

- 主线 `tower_kind = "deterministic"`（阶段一），**不启用高斯塔**；
- 高斯实现完整保留在 `feat/gaussian-probabilistic`，含 25 个单测，可随时复现；
- `uncertainty_report()` 诊断保留在该分支，是判断「换数据集后是否值得启用」的第一道关卡。

复现命令（在 `feat/gaussian-probabilistic` 分支）：

```bash
git switch feat/gaussian-probabilistic
python -m scripts.train_semantic --data-source mooccube --tower-kind gaussian --sparse-tail 2
# 输出会打印不确定性诊断：item_var_cv 接近 0 即说明该扩展在此数据上不成立
```

## 5. 可能可行的方向（按性价比排序）

**方向 1：先把「历史长度 → 不确定性」参数化成显式函数（成本低，可快速证伪）**
不必让模型自己学方差，直接规定 `σ = f(历史长度)`（如 `σ = σ₀ + σ₁/√n`，参数可学）。
这样方差**必然**携带稀疏度信息，能立刻回答「不确定性是否对排序有用」这个问题——
如果这样都无收益，就说明问题不在方差的学习方式，而在设定本身。
风险：这是把假设写死，而非让数据说话；但它能在半天内给出明确判决。

**方向 2：给方差一个真正可学的信息来源——序列（成本高，最接近论文设定）**
用行为**序列**（顺序 + 时间间隔 + 行为类型）编码学生状态，而非拼接文本。
时间间隔的波动、行为的跳变都是「不确定性」的自然信号，
这正是 UKT/U-GLAD 的立足点。代价：需要新增序列编码器与相应数据管道，工作量明显更大，
且**无法保证有效**（取决于数据里是否真有可提取的不确定性结构）。

**方向 3：重新审视评估协议本身（成本低，容易被忽略）**
当前正样本是「测试期新选的课」，负样本是从未见过的课中采样的。
但「不确定」这件事在真实场景里该体现为**排序保守**（把热门/宽泛内容排前），
而不是「把某门新课排得更准」。如果目标是表达不确定性，
也许该换一个能度量「保守性」的指标（例如风险-覆盖曲线、或在低置信用户上度量
热门内容占比），否则可能一直在用错误的尺子量。

**方向 4：换数据或换设定（成本中）**
概率式表示的前提是**同一条需求存在多个有效答案**。
MOOCCube 每门课只有一段简介，一份学生需求对应什么并不含糊，因此方差无用武之地。
若将来有「一个需求对应多门不同方向课程」的场景（例如平台上的学习目标/职业路径），
概率式表示才可能有空间。**建议：先确认场景，再投入建模。**

**不推荐的路径**：在现有拼接文本设定下继续调温度、调正则权重、加大方差上界。
诊断已表明方差与输入几乎无关，调参不会改变这一点。

## 6. 给后来者的检查清单

打算重启这条路线前，先回答：

1. 这份数据里，**同一条需求是否真的有多个有效答案**？（否则分布表示无意义）
2. 有没有**序列**信息可以支撑不确定性的学习？（否则方向 1 是唯一可选项）
3. `uncertainty_report()` 报出的 `item_var_cv` 是多少？
   **接近 0 就不要继续**——它直接说明方差在排序里近似常数。
4. 评估协议度量的是「更准」还是「更保守」？与想验证的假设一致吗？
